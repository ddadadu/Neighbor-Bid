## 1. 서비스 소개

### 대상 사용자
같은 동네에서 중고 물품을 빠르고 공정한 가격에 사고팔고 싶은 주민

### 핵심 기능
고정가 흥정 대신 정해진 시간(5/10/30분) 동안 **실시간 입찰**로 가격을 정합니다. 인기 물품은 마감 직전에 입찰과 접속이 한꺼번에 몰리며, 이때도 중복 낙찰 없이 처리합니다.

| # | 기능 | 사용자 입력 | 결과 |
|---|---|---|---|
| F0 | 닉네임 입장 | 닉네임(2~12자) | 세션 쿠키 발급, 새로고침해도 입장 유지 |
| F1 | 경매 물품 등록 | 사진, 물품명, 설명, 시작가, 경매 시간 | 사진은 S3에 저장, 목록에 '진행 중'으로 표시 |
| F2 | 경매 목록·상세 조회 | 목록에서 물품 선택 | 현재가, 남은 시간, 입찰 기록 |
| F3 | 실시간 입찰 | 입찰 금액 | 같은 경매를 보는 모든 사용자 화면이 즉시 갱신 |
| F4 | 종료 후 자동 정리 | (자동) | 마감 30분 후 경매 기록과 S3 사진 삭제 |
| F5 | 낙찰 후 1:1 채팅 | 메시지 | 판매자와 낙찰자만 실시간 대화 |
**docs 파일 내 기능 시험 결과 첨부**

## 2. AWS 구성도

### 요청 경로

```
[브라우저] ──HTTP / WebSocket──▶ [EC2 :80 · 보안 그룹]
                                   │
                                 nginx ─┬─ /            정적 화면 (HTML/JS/CSS)
                                        ├─ /api/*       ─▶ web:5000 (Flask) ─▶ SQLite (볼륨)
                                        └─ /socket.io/* ─▶ web:5000 (Socket.IO) ─▶ redis (입찰 락)
                                   web ──(IAM 역할)──▶ [S3: neighbor-bid/items/*]
[브라우저] ◀── 사진 URL로 직접 조회 ── [S3]
```

- 리전: 아시아 태평양(시드니) `ap-southeast-2`
- EC2 안에서 Docker Compose로 nginx, web, redis 컨테이너를 실행하며, 외부에는 nginx(80)만 열려 있습니다.

### 서비스 선택 이유

| 서비스 | 역할 | 선택 이유 |
|---|---|---|
| **EC2** | Docker Compose 앱 실행 | 로컬에서 검증한 Compose 구성을 그대로 실행 |
| **S3** | 물품 사진 저장 | 서버와 분리된 저장소라 서버를 다시 만들어도 사진이 유지됨 |
| **IAM 역할** | EC2 → S3 접근 | 액세스 키를 서버에 두지 않고, `items/*` 업로드·삭제만 허용 |

**동시 입찰 처리**: Redis 락으로 같은 물품의 입찰을 하나씩 처리하고, DB는 "현재가보다 높을 때만 갱신"하는 조건부 UPDATE로 최종 판정합니다.

**ELB · Auto Scaling 검토**: 입찰이 몰리는 시간이 마감 직전 1~2분으로 짧고, 상시 비용이 드는 ALB와 다중 인스턴스는 적용하지 않았습니다. 확장할 경우 DB를 RDS로, Redis를 ElastiCache로 분리하고 Auto Scaling 그룹과 ALB(스티키 세션)를 두며, 최대 수량 제한과 예산 알림으로 비용을 관리합니다.

## 3. 실행 · 배포

### 준비 사항
- Docker, Docker Compose
- S3 버킷(`items/*` 공개 읽기), IAM 역할(S3 PutObject·DeleteObject), EC2(보안 그룹 22·80, IAM 역할 연결)

### 환경변수 (`.env`)
`.env.example`을 복사해 작성합니다. EC2에서는 AWS 액세스 키를 넣지 않고 IAM 역할을 사용합니다.


### 명령
```bash
git clone https://github.com/ddadadu/Neighbor-Bid.git
cd Neighbor-Bid
nano .env
docker compose up -d --build
curl http://localhost/api/health      # {"db":true,"redis":true,"status":"ok"}
```

### 포트 · 접속 주소
| 환경 | 포트 | 접속 주소 |
|---|---|---|
| EC2 | 80 | http://16.176.51.20/ |
| 로컬 | 8080 | http://localhost:8080 |

## 4. 검증

시험 환경: local, 배포 주소 http://16.176.51.20/, 브라우저 3개(A 판매자 / B 입찰자·낙찰자 / C 제3자)

| 기능 | 구분 | 입력 | 기대 결과 | 실제 결과 |
|---|---|---|---|---|
| F0 | 정상 | 새 닉네임 입장 | 메인 이동, 새로고침해도 유지 |  |
| F0 | 실패 | 사용 중인 닉네임 | "이미 사용 중인 닉네임입니다." | |
| F1 | 정상 | 사진 포함 등록 | 목록에 표시, S3에 파일 생성 | |
| F1 | 실패 | 6MB 사진 / 이미지가 아닌 파일 | 오류 메시지, 등록 안 됨 | |
| F2 | 정상 | 물품 상세 조회 | 현재가, 카운트다운 표시 | |
| F2 | 경계 | 마감된 물품 | '낙찰/유찰' 표시, 입찰 버튼 비활성 | |
| F3 | 정상 | B가 현재가+500원 입찰 | A·C 화면 즉시 갱신 | |
| F3 | 실패 | 판매자 본인 입찰 / 현재가 이하 금액 | 입찰 거부 | |
| F4 | 정상 | 마감 후 유예 시간 경과 (시험 시 1분) | 목록·S3에서 삭제 | |
| F4 | 경계 | 마감 직후 | '종료' 표시, 사진 유지 | |
| F5 | 정상 | 판매자와 낙찰자가 메시지 전송 | 양쪽 즉시 표시 | |
| F5 | 실패 | 제3자가 채팅 주소로 접근 | "판매자와 낙찰자만 이용할 수 있는 채팅입니다." | |
